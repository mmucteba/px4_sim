# px4_sim — DATABOSS PX4/Gazebo GNSS-denied navigation research

Simulation rig for testing whether a quadrotor can navigate with GNSS removed, using a
downward camera (optical flow) and a downward rangefinder — scored against Gazebo ground
truth rather than against the estimator's own opinion of itself.

PX4 SITL + Gazebo Harmonic, driven by a scenario-based runner and a web dashboard for
launching flights, composing vehicles, and reviewing evidence.

## The project lives in [`databoss_px4_sim/`](databoss_px4_sim/)

```bash
git clone git@github.com:mmucteba/px4_sim.git px4_sim
cd px4_sim/databoss_px4_sim
sudo scripts/deploy/bootstrap.sh --yes
```

Bootstrap provisions system packages, PX4 at a pinned commit with its patches, both
Python virtualenvs, the terrain generator, the dashboard systemd unit, and the vehicle
model/airframe inventory. It finishes by running the deployment check, which should print
`33 OK, 0 FAIL, 0 WARN, 0 SKIP`.

**Read [`databoss_px4_sim/README.md`](databoss_px4_sim/README.md) next** — that is the
real documentation: architecture, the frame and time contract, the run-evidence contract,
completed phases, and the current open issues.

## Host requirements

Ubuntu 24.04 (noble) — the OSRF apt source in `bootstrap.sh` is pinned to it — Gazebo
Harmonic 8.14.0, **at least** 2 cores / 4 GB RAM, and 15 GB free disk. Treat those as a
floor rather than a recommendation: the reference host is 2 cores / 3 GB, and
`bootstrap.sh` itself warns that `make px4_sitl_default` "takes a long time on a 2-core
host".

## Two things to know before trusting a result

**Optical flow is not yet validated.** Angular flow rate is velocity ÷ height, and the
current scenarios hover at 0.2 m/s at 15 m — 0.0133 rad/s — against an assigned
observation-noise floor of 0.303 rad/s (`EKF2_OF_N_MIN` 0.3). Measured airborne, the
assigned noise is 4–7× the signal, so the EKF innovation gate cannot discriminate: runs
fuse ~99% of flow samples while the flow contributes almost nothing, and
`run_stats.json` reports `gate_discriminating: false`. No run has passed
`check_flow_velocity_sign`. Closing this needs a flight profile with real translation,
not a code change.

**Ground truth is the judge, not the estimator.** PX4's local position can look perfectly
smooth while the vehicle physically drifts. Every run is scored against Gazebo truth, and
a run that cannot be evidence-checked is not a useful run.

## Not included in this repository

- `experiments/runs/` — flight output, regenerated by flying
- Recorded ULogs and their derived CSVs
- `.dashboard_token` — per-host write-access secret, never shared

Terrain and flat worlds **are** included (`databoss_px4_sim/generated_worlds/`, ~27 MB),
because every scenario references one and a clone without them cannot fly anything.
